## 1. Назначение

Бот закрывает один бизнес-процесс: **расшифровка совещаний превращается в структурированный
протокол и попадает в Яндекс Вики**.

Цепочка выглядит так:

```
Секретарь → письмо с темой «Конспект встречи» + .txt-вложение
         ↓
Бот (IMAP, фоновый цикл каждые 5 минут) → забирает, НЕ снимая флаг \Seen
         ↓
Уведомление в Telegram с кнопками
         ↓
Рекрутер жмёт «📝 Расшифровать и разместить в wiki»
         ↓
Бот классифицирует конспект по префиксу темы → выбирает промпт
         ↓
Нейросеть разворачивает конспект в протокол по этому промпту
         ↓
Две страницы в Вики: оригинал конспекта + готовый протокол
```

Три отличия от обычного саммарайзера, которые определяют всю конструкцию:

1. **Оригинал сохраняется рядом с протоколом.** Конспект уходит в Вики без единой правки,
   протокол — в соседнюю папку. Всегда можно проверить, из чего сделан вывод.
2. **Промпт выбирается по теме письма, а не один на всё.** Маппинг «префикс темы → подраздел
   Вики» (`bot.py:1381-1395`) решает, какой шаблон применить.
3. **Публикация в Вики идемпотентна.** Перед записью проверяется существование страницы,
   повторная обработка того же письма не создаёт дубль.

## 2. Стек и зависимости

| Слой | Технология |
|---|---|
| Telegram | aiogram 3.x, FSM через `StatesGroup` |
| Почта | `imaplib` (stdlib), `BODY.PEEK[]` — флаг `\Seen` не снимается при чтении |
| Нейросеть | OpenAI-совместимый API через `hunttech_bot_common` |
| Вики | `httpx` к `https://api.wiki.yandex.net/v1` |
| Хранилище | JSON-файлы + PostgreSQL (через `db.py` / `integrations/db_adapter.py`) |
| Конфигурация | `python-dotenv`, `TG_TOKEN` в `.env` |
| Общая библиотека | `hunttech_bot_common` — контроль доступа, мультифоллбэк AI, трекинг расходов |

Из `hunttech_bot_common` импортируются `access_manager`, `create_fallback_ai_client`,
`create_multi_fallback_ai_client`, `OPENROUTER_FREE_MODELS`, `AIResponse`,
`send_startup_changelog` (`bot.py:33-44`).

## 5. Фоновая работа: опрос почты

Цикл `check_new_conspects()` (`bot.py:8620-8718`), запускается в `main()` через
`asyncio.create_task` (`bot.py:8718`).

```
каждые 300 секунд (5 минут, bot.py:8625):
    для каждого пользователя с заполненными email и password:
        items = fetch_new_notes(user_id)          # IMAP
        отфильтровать уже отправленные (notified_comms.json)
        для каждого нового:
            отправить уведомление 🔔
            если настроена Вики и режим не «off»:
                сохранить в wiki_pending.json
                приложить кнопки «Расшифровать и разместить в wiki» и «Кратко»
```

Особенности, которые легко сломать при правках:

**Фоновый цикл не трогает `notes_cache.json`.** В коде есть явный комментарий
(`bot.py:8701-8706`): список из `/list` — отдельный снапшот, и перезапись кэша фоновым
циклом сбивала индексы кнопок. Уведомления идут через `wiki_pending.json` по короткому ключу.

**Идемпотентность уведомлений** обеспечивается ключом `f"{timestamp}:{display}"` в
`notified_comms.json`. Повторно по тем же письмам уведомление не придёт.

**Пользователи без полного конфига пропускаются** молча (`bot.py:8634-8635`).

## 6. Работа с почтой

### 6.1 Отбор писем

`_filter_and_extract()` (`bot.py:685-777`) — ядро разбора. Фильтрует по `SUBJECT_FILTER`
и достаёт текст конспекта.

Три функции выборки:

| Функция | Строка | Что делает |
|---|---|---|
| `fetch_notes` | 791 | непрочитанные конспекты |
| `fetch_new_notes` | 832 | для фонового цикла |
| `fetch_notes_last_week` | 877 | все за последние 7 дней |

### 6.2 Текст конспекта

Текст берётся из `.txt`-вложения: `extract_txt_attachments()` (`bot.py:606-634`). Это не
побочный эффект — именно txt-вложение является источником конспекта.

### 6.3 Флаг \Seen

Письма читаются через `BODY.PEEK[]`, поэтому флаг `\Seen` не снимается при чтении — конспект
остаётся непрочитанным в почтовом ящике. Это осознанное поведение: конспекты не должны
пропадать из ящика секретаря.

Явное снятие флага выполняется отдельной функцией `_set_email_read()` (`bot.py:1693`) —
то есть пользователь может пометить конспект прочитанным, и он перестанет попадать
в непрочитанные.

### 6.4 Перемещение в корзину

`_move_email_to_trash()` (`bot.py:1856-1937`) с подтверждением у пользователя. Основной
путь — `UID MOVE`; при отказе сервера используется запасной `COPY` + `DELETE`
(`bot.py:1918`).

Перед удалением письма выполняется проверка `_verify_telemost_email()` (`bot.py:1793`) —
контроль, что письмо действительно от того отправителя, которого ждём.

### 7.4 Промпт «Стандартное совещание» (4087 символов)

Самый подробный промпт в наборе. Ключевые части.

**Начало:**

```
Ты — профессиональный корпоративный секретарь и аналитик ООО «ХантТек».

На основе полной расшифровки совещания необходимо подготовить структурированное
управленческое саммари, которое:
точно отражает содержание обсуждения;
фиксирует принятые решения;
выделяет поручения;
определяет ответственных;
фиксирует сроки;
показывает нерешенные вопросы;
позволяет на следующем совещании быстро проверить исполнение предыдущих договоренностей.

Саммари должно быть пригодно для использования руководителями компании как рабочий
управленческий документ.
```

**Раздел 1. ИСХОДНЫЕ ДАННЫЕ.** Перечисляет, что может прийти на вход: расшифровка, дата и
время, название совещания, список приглашённых, дополнительный контекст, поручения с
предыдущего совещания. Далее — 16 типов совещаний (от Совета директоров до совещания по
конкретному клиенту) и прямое указание:

```
Не привязывай структуру саммари жестко к типу совещания. Определяй необходимые тематические
блоки по фактическому содержанию расшифровки.
```

Это противоположность промпту Совета директоров: там структура фиксирована, здесь — нет.

**Раздел 2. ОСНОВНЫЕ ПРИНЦИПЫ** — самый ценный для переноса в HRM.

*2.1. Не придумывать факты.* Запрещено самостоятельно придумывать решения, поручения, сроки,
ответственных, причины проблем, участников, цифры, договорённости. При отсутствии
информации — явно «Не определено на совещании». Отдельно: относительные сроки («завтра»,
«к пятнице», «до конца месяца») преобразуются в конкретную календарную дату, если дата
совещания известна; иначе сохраняется исходная формулировка.

*2.2. Отделять обсуждение от решения.* Решением **не считаются**: предложение,
предположение, гипотеза, идея, спорное мнение, вариант решения, намерение что-либо
дополнительно проверить. Решением считается только то, что участники фактически согласовали
или что руководитель явно поручил.

*2.3. Выделять поручения.* По возможности определить: что сделать, ожидаемый результат,
ответственного, срок, приоритет, зависимость от других задач.

*2.4. Определять присутствие по расшифровке.* Участник присутствовал, если у него есть
реплики. Простое упоминание человека другими участниками присутствием не считается.

**Разделы 3–5.** Формат заголовка (тема, тип совещания, дата, время, продолжительность,
участники с пометкой об отсутствии); краткое управленческое резюме из 3–7 пунктов в начале
документа; основная часть с самостоятельным делением на тематические блоки и списком из 15
возможных категорий.

**Содержимое обрывается на середине.** Последняя строка промпта — `Маркетинг`, это конец
списка категорий раздела 5. Разделов про формат вывода, про поручения списком, про
приоритеты и про заключение в тексте нет. Сравните с промптом Совета директоров, где
приоритеты и заключение прописаны явно.

Практическое следствие: модель не получает указаний на формат вывода вообще — ни длины,
ни обязательных разделов, ни способа оформления. Структуру приходится выводить из
собственной дедукции, и результат менее предсказуем, чем у первых двух промптов.

### 7.5 `GROUP_DIGEST_PROMPT` (`bot.py:3802-3810`)

Дословно:

```
Ты — секретарь IT-компании HUNTTECH. Ниже — протокол встречи. Переработай его в КОРОТКИЙ
ДАЙДЖЕСТ для публикации в рабочей группе:
1) оставь только самое основное: решения, задачи, сроки, ответственные;
2) максимум 10 предложений;
3) используй корректное форматирование Markdown: заголовок, списки (- или 1.), жирный текст
   для ключевого;
4) без воды, вводных фраз и приветствий.
```

Применяется на втором шаге публикации: бот берёт уже готовый протокол и сжимает его до
10 предложений для рабочей группы (`bot.py:3844`). Требование «максимум 10 предложений» —
единственное числовое ограничение, оно проверяемо.

### 7.6 `BRIEF_PROMPT` (`bot.py:3953-3960`)

Дословно:


## 8. Выбор промпта

`process_conspect_to_wiki()` (`bot.py:1503-1685`) — центральная функция. Шесть шагов.

### Шаг 1. Классификация по префиксу темы

`wiki_route_section()` (`bot.py:1381-1395`) перебирает `wiki.routing` — словарь
`{префикс темы: slug подраздела}` — и возвращает первое совпадение по `startswith`
без учёта регистра.

```python
disp_low = display.lower()
for prefix, slug in routing.items():
    if disp_low.startswith(prefix.lower()):
        return slug
return ""
```

Правило однозначное и дешёвое, но хрупкое: тема «Совет директоров — 01.09» подойдёт под
префикс «Совет директоров», а тема «Оперативка по Совете директоров» — нет. Порядок
обхода словаря определяет приоритет: первое совпадение выигрывает, поэтому при пересечении
префиксов побеждает тот, кто выше в словаре.

Если подраздел не найден, бот **не падает**: он предлагает пользователю выбрать промпт
из списка вручную (`bot.py:1543-1547`), возвращая специальный сигнал `PROMPT_CHOICE_NEEDED`.

### Шаг 2. Структура папок

```python
year  = dt.strftime("%Y")                              # 2026
month = f"{dt.strftime('%m')} {_month_name(dt.month)}"  # 09 сентябрь
page  = dt.strftime("%Y.%m.%d")                        # 2026.09.30

conspects_dir = f"{folder}/Конспекты/{year}/{month}"
protocols_dir = f"{folder}/Протоколы/{year}/{month}"
```

Две параллельные ветки: оригиналы и протоколы. Страница называется датой — на одну дату одна
страница в каждой ветке.

Все шесть промежуточных папок создаются явно (`bot.py:1564-1576`), потому что Вики не создаёт
промежуточные страницы автоматически: без этого год и месяц «пропадают» из дерева.

### Шаг 3. Оригинал конспекта

Публикуется дословно, без изменений. Если страница уже есть — повторно не пишется
(`wiki_page_exists()` → ранний выход). Это и есть механизм идемпотентности.

### Шаг 4. Разрешение промпта

Порядок проверки (`bot.py:1597-1632`):

1. **Явно заданная тема** (`prompt_topic` из состояния) — берётся из `prompts.json`.
2. **Корень подраздела Вики** — со страницы `{подраздел}/` читается промпт, очищенный
   функцией `wiki_extract_prompt()` (`bot.py:1363-1378`). Она убирает макрос `{% tree %}`
   и заголовок «Промпт для нейросети», оставляя только текст шаблона.
3. **Запасной вариант** — страница из `wiki.prompt_slug`.
4. **Промптов нет** — бот предлагает пользователю выбрать или создать.

Так промпт можно хранить тремя способами: в `prompts.json`, прямо в Вики или и там, и там.

### Шаг 5. Генерация

```python
user_text = f"Тема: {display}\nДата: {date_str}\n\n{content}"
result = await call_ai(user_id, prompt_text, user_text, system_prompt=None, progress=progress)
```

Текст конспекта уходит в user-сообщении, инструкции — в system. Явная дата и тема
передаются отдельными строками, чтобы модель могла превращать относительные сроки
в календарные (правило 2.1 промпта «Стандартное совещание»).

Результат проходит через `_sanitize_ai_md()` (`bot.py:55-73`) — нормализация Markdown
перед сохранением в Вики.

### Шаг 6. Публикация

Короткий вариант публикует протокол в Вики сразу. Длинный (`publish_wiki:`) предлагает
дополнительно дайджест в рабочую группу.

### 9.3 Извлечение промпта со страницы

`wiki_extract_prompt()` (`bot.py:1363-1378`):

```python
text = re.sub(r"\{%\s*tree\s*%\}", "", content)
marker = re.search(r"Промпт\s+для\s+нейросети", text, re.IGNORECASE)
if marker:
    text = text[marker.start():]
    text = re.sub(r"^[#*\s]*Промпт\s+для\s+нейросети[:*]*", "", text, flags=re.IGNORECASE)
```

Конвенция простая: всё после заголовка «Промпт для нейросети» считается шаблоном.
Если заголовка нет — берётся вся страница целиком.

## 10. Работа с нейросетью

### 10.1 Цепочка моделей

`call_ai()` (`bot.py:7638`):

1. **Основная модель** — из настроек пользователя, по умолчанию `deepseek-v4-flash`.
2. **Первый fallback** — `OPENROUTER_FALLBACK_MODEL`, по умолчанию
   `nvidia/nemotron-3-super-120b-a12b:free`.
3. **Цепочка бесплатных моделей** — `OPENROUTER_FREE_MODELS` из `hunttech_bot_common`,
   перебирается по очереди.

Цепочка строит `_build_multi_fallback_ai_client()` (`bot.py:7535`), который оборачивает
`create_multi_fallback_ai_client`. Отдельный `_build_fallback_ai_client()` (`bot.py:7602`)
обслуживает одиночный fallback и, в отличие от мульти-варианта, **не передаёт прокси** —
при недоступности прокси в основном пути fallback-цепочка пойдёт напрямую.

### 10.2 Параметры вызова

```
temperature = 0.2    — почти детерминированный вывод
max_tokens  = 4000   — потолок для длинного протокола
```

Низкая температура выбрана осознанно: саммари Совета директоров идёт в документооборот,
и разброс формулировок между запусками нежелателен.

### 10.3 Обработка отказов

Все вызовы обёрнуты в `try/except`, в лог пишется причина. Пользователю при ошибке
показывается текст, а не traceback. Причины отказа перечислены явно: лимит длины конспекта,
лимит Telegram, API-ошибка, файлы не загружены, нет прав, Вики недоступна.

## 12. Обработка ошибок

Стратегия единая: **сбой фиксируется в лог, пользователь получает понятный текст,
состояние бота не повреждается.**

| Что | Как |
|---|---|
| Нет настройки Вики | Понятное сообщение, предложение `/setup_wiki` |
| Ключ Вики невалиден | Текст про проверку ключа и OrgID |
| Ошибка HTTP Вики | Текст с кодом ответа |
| Конспект не найден по теме | Подсказка про `SUBJECT_FILTER` |
| Промпт не найден | Предложение выбрать из списка или создать |
| Конспект длиннее лимита | Указание на лимит Telegram (4096) |
| AI недоступен | Текст с причиной |
| Письмо не от ожидаемого отправителя | Отказ с объяснением |

Механика воронок важна: в `main()` сначала регистрируются хендлеры, и только потом
запускается фоновый опрос почты (`bot.py:8718`), чтобы бот отвечал на команды, даже если
IMAP недоступен.

## 13. Найденные дефекты

Проверено на текущем состоянии кода, 30.09.2026.

### 13.1 Латентная ошибка: выбор промпта зависит от `progress`

**Серьёзность: средняя. Сейчас не проявляется, но сломается при первом же вызове без прогресса.**

`bot.py:1594-1598`:

```python
    if progress:                              # 1594 — отступ 4
        await progress.done()                 # 1595 — отступ 8
                                             # 1597 — комментарий, парсер его игнорирует
        prompt_text = None                    # 1598 — отступ 8, это всё ещё тело `if`
        if prompt_topic is not None:          # 1599
```

Строка 1598 имеет отступ 8 и потому продолжает блок `if progress:`, а не начинает новый.
Весь код разрешения промпта — строки 1598–1632 — выполняется **только при `progress` не None**.

Файл при этом компилируется без ошибок (`python -m py_compile bot.py` — код возврата 0),
поэтому дефект не видно ни проверкой синтаксиса, ни запуском.

Сейчас не стреляет, потому что все шесть вызовов
`process_conspect_to_wiki()` (`bot.py:3168`, `3270`, `3387`, `3492`, `3592`, `3669`)
непосредственно перед вызовом создают `WikiProgress(...)` — объект всегда истинен.

Но сигнатура функции объявляет `progress: WikiProgress | None = None`, то есть `None`
заявлен как допустимое значение. Любой будущий вызов без прогресса получит
`UnboundLocalError` на строке с `call_ai` — и не в момент вызова, а позже, когда
поток дойдёт до обращения к переменной.

**Исправление:** сдвинуть блок 1598–1632 на отступ 4, чтобы он стал самостоятельным
уровнем функции.

## 15. Порядок работы

### 15.1 Разовое разворачивание

1. `pip install -r requirements.txt`
2. Создать `.env` из шаблона, вписать `TG_TOKEN` и `MASTER_ADMIN_ID`
3. Вынести реквизиты прокси из `bot.py:7598` в `.env`
4. `python bot.py` — бот поднимется и начнёт опрашивать почту

### 15.2 Настройка пользователя

1. `/start` → запрос доступа
2. Админ подтверждает: `/user add <id>`
3. Пользователь: `/setup` → почта в четыре шага (email → сервер → логин → пароль)
4. Пользователь: `/setup_ai` → ключ и модель
5. Пользователь: `/setup_wiki` → OAuth-ключ и OrgID
6. `/setup wiki folder <slug>` — подраздел для своих конспектов
7. `/setup wiki mode auto` — автоматическая публикация вместо ручной кнопки

### 15.3 Ежедневная работа

Бот работает сам: каждые 5 минут забирает конспекты, присылает уведомления.
Действия нужны только в двух случаях — выбрать промпт для нестандартной темы
и нажать «Опубликовать в группе», если нужен дайджест.
